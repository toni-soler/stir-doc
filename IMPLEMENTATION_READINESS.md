# Implementation readiness

Foundation validation passed; 0.2 added a full marketplace MVP (ParticipantProfile, Offer, Negotiation, Agreement, AgreementSnapshot); 0.3 adds real economic exchange (client-signed osTRIS EXCHANGE proposals, commit, balance/receipt, reconciliation - see DOMAIN_MODEL.md/OSTRIS_INTEGRATION.md); 0.4 adds the public-pilot surface (photos/avatars, notifications, multi-device credential lifecycle, minimal moderation, instance branding, production-deployment prep - see DOMAIN_MODEL.md's "Public pilot additions" section). None of the four is a production release: a production-like Docker path is prepared (object storage, one-shot migrations, reverse-proxy-safe TLS handling, secret-hygiene fail-fast checks) but not executed against any real destination server. VALIDATION.md records executed checks; unexecuted checks are never PASS.

The 0.1/0.2 economic blockers (public osTRIS discovery/read/status contracts, credential onboarding, canonical signing payload retrieval) are resolved in 0.3 - osTRIS gained a minimal discovery/provisioning/status surface in its own repository, and STIR's client generates and holds its own Ed25519 keys. 0.4 resolves the multi-credential-rotation gap too - osTRIS gained a minimal credential add/revoke/list surface on top of its EXISTING credential/controller_credential_binding contract (see OSTRIS_INTEGRATION.md's "IMPLEMENTED IN 0.4" section) - without any change to AccountControlPolicy or threshold semantics. Remaining deferred: governed multi-controller policies and M-of-N multi-device signing UI (osTRIS's threshold semantics already support M-of-N; STIR only ever provisions 1-of-N so far), a non-WebCrypto signing fallback (not currently needed). Anonymous publication and a real public deployment at any hostname remain outside 0.4.

Shell 0.3 supplies React/router/i18n/authenticated HTTP but not CRUD or active tenant in its SDK, and hardcodes two module hosts. stir-main carries a pinned-source adapter. Ledger/osTRIS Dockerfiles reference stale 0.2.0 filenames; composition-owned Dockerfiles build public 0.3 sources. Published upstream commits are unchanged. The independent idax-shell fix and reviewed compatibility patches are documented in SHELL_COMPATIBILITY.md.
