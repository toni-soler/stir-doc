# Implementation readiness

Foundation validation passed; 0.2 added a full marketplace MVP (ParticipantProfile, Offer, Negotiation, Agreement, AgreementSnapshot); 0.3 adds real economic exchange (client-signed osTRIS EXCHANGE proposals, commit, balance/receipt, reconciliation - see DOMAIN_MODEL.md/OSTRIS_INTEGRATION.md). None of the three is a production release. VALIDATION.md records executed checks; unexecuted checks are never PASS.

The 0.1/0.2 economic blockers (public osTRIS discovery/read/status contracts, credential onboarding, canonical signing payload retrieval) are resolved in 0.3 - osTRIS gained a minimal discovery/provisioning/status surface in its own repository, and STIR's client generates and holds its own Ed25519 keys. Remaining deferred: multi-credential rotation and governed multi-controller policies (intentionally out of scope for osTRIS's provisioning convenience surface), a non-WebCrypto signing fallback (not currently needed). Attachments, anonymous publication, moderation and production deployment remain outside 0.3.

Shell 0.3 supplies React/router/i18n/authenticated HTTP but not CRUD or active tenant in its SDK, and hardcodes two module hosts. stir-main carries a pinned-source adapter. Ledger/osTRIS Dockerfiles reference stale 0.2.0 filenames; composition-owned Dockerfiles build public 0.3 sources. Published upstream commits are unchanged. The independent idax-shell fix and reviewed compatibility patches are documented in SHELL_COMPATIBILITY.md.
